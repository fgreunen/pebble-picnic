# Pebble Picnic — agent guide

Offline children's slingshot game: plain JavaScript, Canvas, Web Audio and vendored Matter.js. Keep `PLAY.cmd` / `index.html` playable without a server, installation or internet. Node is development-only; no `npm install`.

- Start with the current entry in [PROGRESS.md](PROGRESS.md), relevant requirements/amendments in [TODO.md](TODO.md), and relevant sections of [DEVELOPMENT.md](DEVELOPMENT.md). History is reference, not required reading. New user requirements win; T12 replaces T3's impact-triggered bombs. A backlog is not an instruction to implement everything.
- Keep rules in `src/physics.js`, layouts/ammo in `src/levels.js`, and input/rendering/audio in `src/game.js`. Preserve browser/CommonJS exports, script order, local assets and vendor attribution. Avoid unrelated architecture, dependency or formatting changes.
- Keep generated screenshots, logs, reports and test snapshots outside the repository. Use `tools/artifacts.cjs` for the project's system-temp directory; only source, required game assets, fixtures and documentation belong in Git. Store browser captures in its `screenshots` subfolder.
- Preserve finite typed ammo, cancellation without a shot, continued simulation after reload, bounded outcomes, deterministic physics, separate simulation/active-real-time clocks, and reset/pause cleanup. DEVELOPMENT records the non-obvious lifecycle constraints.
- Run affected standalone suites during iteration, then `npm test` once on final runtime/test changes. Use simulated time, not sleeps. UI changes need focused localhost browser checks, including a smaller window. Documentation-only changes need content/link checks. Never regenerate fixtures just to pass tests; the audit and searches have documented write effects.
- For substantial work, use 1–2 helpers only where independent investigation/testing/review is useful. Keep small or tightly dependent work with the lead; use parallel processes for routine commands. Give explicit file ownership, input identity and acceptance criteria. Model guidance is in DEVELOPMENT.
- Other chats may share this folder. Record owner/scope/files in PROGRESS before substantial edits; reread shared files and preserve others' work. One writer per overlapping file/fixture; test frozen inputs when edits overlap. Do not assume Git exists.
- Finish with a concise PROGRESS entry: changes, exact checks/results and tested identity, remaining issues/next action, running jobs. Update requirements/player guidance only when changed. Archive old handoffs with working links; do not duplicate evidence across documents.
